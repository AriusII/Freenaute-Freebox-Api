================
Parental Control
================

With the parental control API you can define rules to limit or block
access to internet for any host on your local network. With a planning
you can change the access policy during the day.

The different access policies are:

============== ======================
filter_state   Description
============== ======================
allowed        access is allowed
denied         access is denied
webonly        access is granted only for HTTP and HTTPS traffic
============== ======================

Parental Control errors
=======================

When attempting to access the parental control API, you may encounter
the following errors:

=========== ======================
error_code  Description
=========== ======================
inval       invalid request
exist       a rule already exists for this host
noent       invalid rule id
=========== ======================


Parental Filter Config
======================

Parental filter configuration allow you to set the default
filter_state to apply to hosts without rules on your network

.. json:object:: ParentalFilterConfig

   .. json:property:: default_filter_mode enum

      see available filter_state

Parental Filter Planning
========================

Parental filter planning let you define the parental filter policy
based on the week day and the hour.

Parental filter planning have the following attributes:

.. json:object:: ParentalFilterPlanning

   .. json:property:: resolution int [ro]

      planning resolution : number of planning slots per day, e.g. 48
      means that each slot represent 30 minutes

   .. json:property:: cdayranges string[]

       list of custom day range, each custom day range represents a
       group of days for which you want to use a different planning
       than other week days.

       For instance a custom day range can contain the list of you children
       holidays

       ============================   ===================================
       cdayranges                     Description
       ============================   ===================================
       :fr_bank_holidays              French bank holidays
       :fr_school_holidays_a          French school holidays - Zone A
       :fr_school_holidays_b          French school holidays - Zone B
       :fr_school_holidays_c          French school holidays - Zone C
       :fr_school_holidays_corse      French school holidays - Corse
       ============================   ===================================

       each cdayranges can be a coma separated list of cdayranges, for
       instance ":fr_bank_holidays,:fr_school_holidays_b"

   .. json:property:: mapping enum[] [ro]

      array of states for each corresponding planning slots.  the
      array size is : (number of cdayranges + 7) * resolution


Parental Filter rule object
===========================

Parental filter rule objects have the following attributes:

.. json:object:: ParentalFilter

   .. json:property:: id int [ro]

       filter id

   .. json:property:: macs string[]

      the list of mac addresses the rule should be applied to

   .. json:property:: hosts string[] [ro]

      the list of hostnames associated with macs

   .. json:property:: ip string [ro] [DEPRECATED]

      only filled for old rules, you cannot set a rule with an IP

   .. json:property:: desc string

      a description for this rule

   .. json:property:: forced bool

      is set to true, the rule will not use the planning and will
      always stay in the forced_mode

   .. json:property:: forced_mode enum

      the filter policy to use when forced is set to true (see
      filter_state for valid states)

   .. json:property:: tmp_mode_expire int

      if != 0 the rule will not use the planning for the next
      tmp_mode_expire seconds

   .. json:property:: tmp_mode enum

      the filter policy to use when tmp_mode_expire is != 0 (see
      filter_state for valid states)

   .. json:property:: scheduling_mode enum [ro]

      ================= ===============================================
      scheduling_mode   Description
      ================= ===============================================
      forced            filter_state is forced to forced_mode
      temporary         filter_state is temporary set to tmp_mode for
                        the next tmp_mode_expire seconds
      planning          filter_state is set using the planning
      ================= ===============================================

   .. json:property:: filter_state enum [ro]

      =============== ======================
      filter_state    Description
      =============== ======================
      allowed         access is allowed
      denied          access is denied
      webonly         access is granted only for HTTP and HTTPS traffic
      =============== ======================

   .. json:property:: current_mapping_idx int [ro]

      current index used in planning to compute filter_state (only
      relevant when scheduling_mode is planning)

   .. json:property:: next_change int [ro]

      seconds until next filter_state change 0 means filter_state
      won't change

Parental Filter API
===================

Get parental filter config
--------------------------

.. http:get:: /api/v4/parental/config/

   Get the :json:object:`ParentalFilterConfig`

   **Example request**:

   .. sourcecode:: http

      GET /api/v4/parental/config/ HTTP/1.1
      Host: mafreebox.freebox.fr

   **Example response**:

   .. sourcecode:: http

      HTTP/1.1 200 OK
      Content-Type: application/json; charset=utf-8

   .. sourcecode:: javascript

      {

          "success": true,
          "result": {
              "default_filter_mode": "allowed"
          }

      }


Update parental filter config
-----------------------------

.. http:put:: /api/v4/parental/config/

   Update the :json:object:`ParentalFilterConfig`

   **Example request**:

   .. sourcecode:: http

      PUT /api/v4/parental/config/ HTTP/1.1
      Host: mafreebox.freebox.fr

   .. sourcecode:: javascript

      {
         "default_filter_mode": "denied",
      }


   **Example response**:

   .. sourcecode:: http

      HTTP/1.1 200 OK
      Content-Type: application/json; charset=utf-8

   .. sourcecode:: javascript

      {

          "success": true,
          "result": {
              "default_filter_mode": "denied"
